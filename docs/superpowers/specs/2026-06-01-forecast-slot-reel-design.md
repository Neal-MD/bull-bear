# 세로 슬롯 릴 뉴스 예보 — 설계 문서

> 작성일: 2026-06-01 · 작업자: 송창환 + Claude
> 트리거: "이번 라운드 뉴스에 먼저 포커스되게 하고, 슬롯/룰렛 형태로 지난·이번·다음 뉴스를 보여주고 싶다"는 플레이 피드백.

---

## 1. 목표

현재 가로 2박스("이번 칸 사건" + "다음 ▸") 예보 스트립을, **슬롯머신 세로 릴** 형태로 교체한다.

- **이번 라운드**가 가장 크고 환하게(payline) 강조 — 사용자가 먼저 집중.
- **지난 라운드**(직전 1R)는 흐릿하게 살짝만 보이고, 위로 밀거나 탭하면 펼쳐짐.
- **다음 라운드**는 보이되 덜 강조.
- 빤짝거리는(샤인/펄스) 슬롯 UI로 보드게임 느낌 강화.

레이아웃 방향은 비주얼 컴패니언으로 **세로 릴** 확정(가로 릴 대비 참고 이미지에 충실).

## 2. 범위 / 비범위

**범위:** 예보 표시 UI(렌더·CSS·터치 조작) + 지난 라운드 데이터 보관 + 인앱 문서 한 줄 + DEV_NOTES 기록.

**비범위(중요):** 게임 로직·확률·주가 이동·이벤트 덱·밸런스 **일절 변경 없음.** 따라서 `sim/simulate.js`·`sim/sweep.js` 패리티 영향 없고 시뮬 재검증 불필요.

## 3. 확정된 동작 규칙

| 항목 | 결정 |
|---|---|
| 릴 범위 | 예보 길이(forecastLen)만큼 확장 — 고급(1)=2칸(지난·이번), 표준(2)=3칸(+다음), 초급(3)=4칸(+다다음, 더 흐릿) |
| 지난 기록 | 직전 1라운드만 |
| 조작 | 드래그(scroll-snap) + 탭(scrollIntoView) 둘 다 |
| 기본 포커스 | 매 렌더 후 항상 "이번"에 스냅 |

## 4. 데이터 변경

- `G.lastForecast` 신규 필드. 게임 시작(`startGame`) 시 `null`로 초기화.
- `advanceRound()`에서 `G.forecast.shift()` **직전에** `G.lastForecast = G.forecast[0]`로 끝난 슬롯 저장.
- undo 스냅샷이 `G` 전체를 복제한다면 자동 포함됨 — `undoTurn` 경로에서 `lastForecast`가 보존되는지 확인만.

**알려진 단순화:** '이벤트 뒤집기' 카드로 효과가 반전된 라운드는, 지난 릴에 *예보 당시 방향*이 표시된다(실제 결과와 다를 수 있음). 실제 결과는 기존 결산 화면이 보여주므로 교육상 문제 없음. 스펙에 명시해 혼란 방지.

## 5. 렌더링

- `fcStripHTML()` → `fcReelHTML()`로 교체. `renderTurn()`의 호출부(현재 `${fcStripHTML()}`) 교체.
- 칸 구성(위→아래):
  - **지난**: `G.lastForecast`가 있을 때만(라운드 ≥ 2). 흐릿+축소.
  - **이번**: `G.forecast[0]`. 포커스(payline·확대·글로우).
  - **다음**: `forecastLen ≥ 2` 이고 마지막 라운드 아님 → `G.forecast[1]`. 그 외(고급 forecastLen=1, 또는 12R) → `❓ 비공개` 플레이스홀더. 덜 강조.
  - **다다음**: `forecastLen ≥ 3` 이고 `G.forecast[2]` 존재 → 표시(가장 흐릿). 마지막 직전 라운드 등 데이터 없으면 생략.
- 각 칸 내부 사건 렌더는 기존 `miniEvHTML(ev, fog)` **재사용** → 배당 이벤트·고급 안개(`fog && i===1`로 2번째 사건 방향 숨김) 로직 그대로 유지.

## 6. 조작 (아이패드 터치)

- 세로 컨테이너: CSS `scroll-snap-type: y mandatory`, 각 칸 `scroll-snap-align: center`. 손 드래그 = 네이티브 관성 스크롤.
- 위/아래 페이드 마스크(mask-image 그라데이션)로 릴이 도는 느낌.
- 흐릿한 칸 **탭** → 해당 칸 `scrollIntoView({block:'center', behavior:'smooth'})`로 포커스. (탭 시 그 칸을 일시적으로 강조하는 처리는 CSS `:focus`/스크롤 위치 기반 — 단순 구현 우선.)
- `renderTurn()`은 매 행동마다 `#app` innerHTML을 재생성하므로, 렌더 직후 릴의 스크롤 위치를 "이번" 칸 중앙으로 설정하는 코드 필요(렌더 후 1회 실행: 예) `requestAnimationFrame`으로 이번 칸 offsetTop 반영).

## 7. 비주얼 (impeccable 단계에서 마감)

- 슬롯 프레임: 금속/광택 테두리, 중앙 payline 강조 밴드, 위·아래 페이드.
- 포커스 칸: 따뜻한 골드(`--gold` 계열) payline, 확대(scale ~1.04), 글로우.
- 흐릿 칸: 저투명(past ~.32 / next ~.6 / 다다음 더↓), 탈채도, 축소.
- **빤짝거림:** 포커스 payline에 샤인 스윕 키프레임 + 은은한 펄스. 초3이 산만하지 않을 강도(과한 점멸 금지, 교육 도구 원칙).
- 기존 색 규약 유지: 초록=상승, 빨강=하락, 노랑=배당.

## 8. 엣지 케이스

- **1라운드**: 지난 칸 없음 → 릴은 이번(+다음...)로 시작, 이번에 스냅.
- **12라운드(마지막)**: 다음 = `❓ 비공개`(막판 올인 방지 원칙 유지).
- **고급 모드**: `forecastFog`로 이번/다음 2번째 사건 방향 ❓(기존 동작 유지). forecastLen=1이라 다음은 `❓ 비공개`.
- **상장폐지**: 이미 `resolveRound`에서 무관 이벤트가 정리된 뒤 `lastForecast`에 저장되므로 추가 처리 불필요.

## 9. 아이패드 세로(820×1180) 제약

- 세로 릴은 기존 가로 스트립보다 키가 큼 → 흐릿 칸(지난/다음/다다음)을 **충분히 압축**(peek 높이)해 아래 회사 보드가 잘리지 않게.
- 구현 후 820×1180에서 보드 6타일 + 액션바가 한 화면에 들어오는지 확인(무스크롤 원칙).

## 10. 문서 갱신

- 인앱 `DOCS.rules`의 "시장 예보 보는 법" 문단을 릴 기준으로 갱신(지난·이번·다음, 이번이 강조, 밀어서 보기).
- `docs/DEV_NOTES.md` 또는 `docs/DEV_HISTORY.md`에 UI 변경 이력 추가(**밸런스 무관** 명시).

## 11. 검증 (완료 기준)

- [ ] 브라우저에서 한 판 진행: 1R(지난 없음) → 중반(지난·이번·다음) → 12R(다음 ❓) 모두 정상.
- [ ] 초급(다다음 보임)·표준·고급(다음 ❓, 안개) 3난이도에서 칸 구성 정확.
- [ ] 드래그·탭 둘 다 동작, 매 행동 후 이번에 리셋.
- [ ] 배당 이벤트·undo·정보입수와 충돌 없음.
- [ ] 아이패드 세로에서 보드 안 잘림.
